# v0.1 - Fechamento de lacunas e decisoes bloqueantes

## Objetivo
Transformar o planejamento em execucao pratica, removendo ambiguidades de produto e riscos tecnicos antes de iniciar implementacao pesada.

## A. Decisoes bloqueantes (resolver antes do desenvolvimento principal)

1. Escopo de automacao
- Opcao A: somente web automation (Playwright).
- Opcao B: somente desktop RPA Windows.
- Opcao C: ambos, com roteamento por capacidade.
- Recomendacao para v0.1: Opcao A (somente web automation).

2. Infra de execucao
- Web: Linux headless em container.
- Desktop RPA (se entrar no futuro): worker Windows com sessao interativa.
- Decisao v0.1: sem desktop RPA no caminho critico.

3. Stack de fila
- Escolher 1: Redis Streams ou RabbitMQ.
- Recomendacao v0.1: Redis Streams (menor complexidade inicial).

4. Secret store
- Escolher 1 provider para v0.1.
- Recomendacao v0.1: iniciar com provider unico e interface de abstracao (secret_id + provider fixo).

5. Artifact store
- Escolher persistencia de screenshots/html/logs.
- Recomendacao v0.1: bucket unico com ACL minima e retenção curta.

6. Provedor LLM
- Definir modelo, custo alvo e politicas de privacidade.
- Recomendacao v0.1: 1 provedor, 1 modelo, temperatura baixa para estabilidade.

## B. Modelo de ameaca minimo (codigo Python gerado por IA)

1. Execucao em ambiente isolado (container descartavel para web bots).
2. Usuario sem privilegio administrativo no worker.
3. Sem montagem de disco host sensivel.
4. Lista permitida de dominios para acesso de rede, quando viavel.
5. Bloqueio de bibliotecas/comandos perigosos por politica de execucao.
6. Nunca executar bot sem validacao de contrato v1 e sem origem auditada.

## C. Ajuste de escopo da v0.1 (fatia vertical)

### Entrega v0.1 reduzida e realista
1. Somente web automation (Playwright).
2. 1 fila, 1 tipo de worker, 1 secret provider, 1 artifact store.
3. Fluxo: criar bot -> ad_hoc_test -> aprovar -> publicar -> executar agendado.
4. Estados minimos: draft, approved, published.
5. Sem multi-tenant completo na v0.1 (apenas tenant default).

### Itens explicitamente adiados
1. Desktop RPA Windows (abrir programa/clicar GUI desktop).
2. Sete estados completos de ciclo de vida.
3. Alertas avancados e dashboard completo.
4. Politica sofisticada de cancelamento e reatribuicao.

## D. Contrato v1 - complementos obrigatorios

1. Publicar JSON Schema formal do envelope.
2. Definir schema por bot para campo params.
3. Definir catalogo de error_code versionado.
4. Definir contrato de heartbeat (payload + endpoint).
5. Definir cancelamento (polling de cancel_flag por run_id).
6. Definir idempotencia com unique constraint em run_id + dedup na fila.
