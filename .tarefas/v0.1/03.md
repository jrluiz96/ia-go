# v0.1 - Arquitetura de referencia

## Componentes
1. UI Web
- Criacao do bot por NL.
- Teste imediato.
- Publicacao e acompanhamento.

2. API Go
- CRUD de bots e versoes.
- Validacao de contrato.
- Controle de ciclo de vida.
- Integracao com LLM para geracao de codigo.

3. Scheduler Go
- Avalia cron/timezone.
- Cria disparos de execucao.

4. Dispatcher Go
- Publica jobs na fila.
- Garante idempotencia por run_id.

5. Worker Python
- Consome job.
- Executa bot com contrato v1.
- Retorna status/result/error.

6. PostgreSQL
- Persistencia de bots, versoes, runs, eventos.

7. Queue (Redis ou RabbitMQ)
- Desacoplamento entre disparo e execucao.

8. Secret Store
- Guarda credenciais e certificados.

## Fluxo principal
1. Usuario cria bot na UI.
2. API chama IA com template de geracao.
3. Usuario testa em ad_hoc_test.
4. Usuario salva versao.
5. Revisor aprova.
6. Publicacao ativa bot_version.
7. Scheduler dispara run.
8. Worker executa e reporta.
9. UI mostra historico e detalhes.

## Decisoes tecnicas
1. Contrato de execucao JSON versionado.
2. Uma versao ativa por bot na v0.1.
3. Runtime deterministico sem decisao por IA.
4. Roteamento por capacidade (linux_headless/windows_host/windows_gui).

## NFRs minimos
1. Timeout por run e por etapa critica.
2. Retry com backoff apenas para erro transitorio.
3. Logs estruturados com trace_id/run_id.
4. Heartbeat para detectar travamento.
