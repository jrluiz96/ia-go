# v0.1 - Backlog priorizado

## EPIC A - Authoring com IA
1. A1 - Tela de criacao por linguagem natural.
2. A2 - Integracao com template de geracao.
3. A3 - Fluxo de perguntas pendentes quando faltar contexto.
4. A4 - Persistencia de rascunho do bot.

## EPIC B - Teste imediato
1. B1 - Endpoint ad_hoc_test.
2. B2 - Execucao do bot em worker de teste.
3. B3 - Captura de logs resumidos e artifacts.
4. B4 - Resultado padronizado na UI.

## EPIC C - Governanca de versoes
1. C1 - Estados do ciclo de vida.
2. C2 - Regras de transicao.
3. C3 - Aprovacao manual.
4. C4 - Publicacao/rollback de versao.

## EPIC D - Runtime deterministico
1. D1 - Scheduler por cron/timezone.
2. D2 - Dispatcher e fila.
3. D3 - Worker Python com contrato v1.
4. D4 - Retry/backoff/idempotencia.

## EPIC E - Observabilidade e operacao
1. E1 - Tabela de runs e eventos.
2. E2 - Endpoint de consulta de execucoes.
3. E3 - Heartbeat de run.
4. E4 - Alertas minimos de falha.

## Ordem de implementacao recomendada
1. A1 -> A2 -> B1 -> B2 -> C1 -> C2 -> D1 -> D2 -> D3 -> E1.
2. Itens A3, B3, C3, D4, E2, E3 entram em seguida.
3. Hardening final: E4 + seguranca de secrets + rollback.

## Definition of Ready por tarefa
1. Criterio funcional claro.
2. Dependencias mapeadas.
3. Contrato de API definido.
4. Criterio de aceite escrito.
