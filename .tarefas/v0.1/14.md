# v0.1 - Passo 03: Frontend IA-GO (substituir legado)

## Objetivo
Ler o frontend antigo para reaproveitar apenas padroes uteis de UI/UX e reconstruir o front do produto IA-GO sem heranca Bash.

## Diagnostico atual
1. Projeto legado em front/ possui diversas referencias a Bash.
2. Existem nomes de classes/objetos globais com prefixo Bash.
3. O produto alvo e IA-GO; nomenclatura Bash deve ser removida.

## Diretriz de migracao
1. Manter apenas referencia visual e componentes reaproveitaveis.
2. Reescrever estrutura de navegacao e modulos para dominio IA-GO.
3. Proibir novos nomes com Bash em arquivos, classes, ids e textos.

## Etapas
1. Inventario do front antigo:
- mapear telas reutilizaveis
- mapear dependencias JS/CSS
- mapear pontos de acoplamento com Bash

2. Limpeza controlada:
- remover assets e scripts estritamente Bash
- renomear rotas/titulos/identidade visual para IA-GO

3. Reconstrucao por modulos:
- modulo Criacao de Bot
- modulo Teste Imediato
- modulo Publicacao
- modulo Execucoes

4. Integracao com backend:
- consumo dos endpoints de bots e runs
- exibicao de status e artifacts

## Criterios de aceite
1. Nenhuma ocorrencia de Bash/bash em front/.
2. Fluxo criar -> testar -> publicar funcionando na UI.
3. Layout responsivo em desktop e mobile.
4. Mensagens de erro e estados de carregamento definidos.

## Comando de verificacao obrigatoria
1. Busca textual em front para Bash/bash deve retornar zero.

## Observacao
Apagar tudo e reescrever e permitido, desde que preserve somente o que fizer sentido como base visual e nao mantenha dominio legado.
